# Hunt Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hunts come only from jotihunt.nl (scraped every 60 s, incl. location); the sidebar Hunts card becomes a sync status card with a sync log; all manual hunt registration is removed (server, web, Android).

**Architecture:** The existing scraper cron reads `/hunts` (+ an optional per-hunt detail page) into the `Hunt` model, now with status class, location and accuracy. A pure diff of old vs new hunts produces `HuntSyncEvent`s (new / approved / rejected / points). Sync state lives in memory in the scraper module. Clients poll `GET /hunts/sync` and `GET /hunts/events` (SWR on web, existing polling on Android). Hunt markers, cooldown, prediction and push notifications are fed by synced hunts. The page layout is **estimated** (no login yet): all parsing sits in one pure module with fixtures, so tomorrow's fix = save the real HTML as a fixture and adjust the parser.

**Tech Stack:** Server Bun + Express + Mongoose + puppeteer; web React/Vite/TS + SWR + motion/react + Tailwind; Android Kotlin/Compose M3 Expressive + Retrofit + WorkManager.

## API contract (all tasks rely on this)

```ts
// GET /hunts/sync  (verifyToken; web sessions + Android device tokens)
interface HuntSyncStatus {
  configured: boolean;          // a jotihunt.nl login is set in Beheer
  running: boolean;             // a scrape is in progress right now
  lastSuccessAt: string | null; // ISO
  lastAttemptAt: string | null;
  lastError: string | null;     // Dutch, short, e.g. "jotihunt.nl reageert niet"
  counts: { approved: number; pending: number; rejected: number; total: number };
  points: number;               // sum of points of all synced hunts
}

// GET /hunts/events?limit=50&before=<ISO>  (verifyToken) → newest first
interface HuntSyncEvent {
  _id: string;
  huntId: string;
  area: string;                 // lowercase, e.g. "alpha"
  type: "new" | "approved" | "rejected" | "points";
  points: number | null;        // for approved/points
  at: string;                   // ISO, when our sync noticed it
  huntTime: string | null;      // ISO, the hunt time from the site
  location: { lat: number; lng: number; accuracy: number | null } | null;
}

// GET /hunts (existing route, extended view)
interface SyncedHunt {
  _id: string; siteKey: string; area: string; huntTime: string | null;
  status: "pending" | "approved" | "rejected" | "unknown"; statusText: string; points: number;
  qrCode: string | null; location: { lat: number; lng: number; accuracy: number | null } | null;
  firstSeenAt: string; statusChangedAt: string | null;
}
```
