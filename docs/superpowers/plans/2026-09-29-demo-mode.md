# Demo mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Admin-switchable demo mode that serves a realistic Jotihunt-in-progress from a separate demo database.
**Spec (source of truth for all values, copy and rules):** `docs/superpowers/specs/2026-09-29-demo-mode-design.md`.
**Tech:** Bun 1.4, Express 5, Mongoose 9, bun:test; React 19, shadcn new-york, SWR.

## Global Constraints
- Branch `feat/demo-mode` in both repos (checked out). Bun only via Docker (server: `docker run --rm -u "$(id -u):$(id -g)" -e HOME=/tmp --network jotihunt_default -e MONGO_URI_TEST=mongodb://mongodb:27017/jotihunt-test -v "$PWD":/app -w /app oven/bun:1 bun <args>`; client the same without network/Mongo env).
- The real database must never be modified by demo mode except the `DemoState` settings document. Tests use `MONGO_URI_TEST` databases only.
- Never print/log secrets (.env values, tokens, GEMINI key). UI copy Dutch. Server double quotes / printWidth 200; client single quotes.
- Commits end with `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`. Do not push.

### Task 1: Server — switching infrastructure
Files: `src/demo/demo-state.ts` (DemoState read/write in the real DB, collection `settings`), `src/demo/database-switch.ts` (demo DB name from the Mongo URI, connect/disconnect, drop demo DB, copy users, request gate middleware), `src/demo/demo.controller.ts` + `src/routes/demo.route.ts` (`GET /demo` auth, `POST /demo` admin `{ enabled }`), wiring in `src/index.ts` (gate middleware before routes, start in demo mode when enabled, `isDemoMode()` guard in the jotihunt.nl crons: areas, articles, scraper, logos), `UPLOADS_DIR/demo` for photos in demo mode (photo-store resolves the directory per call). The generator is injected (`generateDemoWorld(now)` from Task 2); for this task use a stub that only copies users. Tests: demo DB name derivation; a real-DB document survives an on/off cycle; users copied; cron guard. Commit.

### Task 2: Server — demo world generator + simulated trackers
Files: `src/demo/generator/*.ts` (seeded PRNG, areas, team assignment k-means, routes + interpolation, RD answer formatting via the existing RD helpers, articles re-timing through the existing article sync, hint cell states + notes, markers, demo users, hunt reports with photos copied from `src/demo/stickers/*.jpg` into `UPLOADS_DIR/demo`), `src/demo/simulated-trackers.ts` (devices/positions/summary distance in demo mode; plug into the tracker controller and the leaderboard service). Also generate ~10 realistic sticker photos once (Chromium in the server image: white sticker "JOTIHUNT 2026" serif title, case-sensitive code, blue handwritten time, on varied backgrounds: pavement, car interior, grass, hand) and commit them under `src/demo/stickers/` (JPEG, ≤ 120 KB each) with a `stickers.json` listing file → code + time. Replace the Task 1 stub. Unit tests per spec "Testing". Commit.

### Task 3: Client — toggle + DEMO badge
Files: `src/hooks/demo.hook.ts` (SWR `/demo` 30 s; `setDemo(enabled)`), Settings admin submenu item + AlertDialog confirm + loading + `window.location.reload()` after success, DEMO badge in `src/components/sidebar/SidebarHeader.tsx` with tooltip; when the polled `enabled` flips while the page is open → reload. Build/lint/tests. Commit.

### Task 4: Verification (controller)
Switch on via the UI as an admin, screenshot map/sidebar/hint board/hint detail/hunts/leaderboard/hunters (desktop + phone), switch off, confirm real data unchanged (counts before/after), clean temp accounts.
